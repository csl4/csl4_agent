# Feature Specification: 多Agent CLI 框架

**Feature Branch**: `001-multi-agent-cli`

**Created**: 2026-09-02

**Status**: Draft

**Input**: User description: "多Agent CLI 模式：执行层 / 能力支撑层 / 核心逻辑层 / 用户交互层（用户、自然语言输入接口、业务Agent模块、CLI Agent模块、环境适配模块、安全防护模块、技能注入模块、通信适配模块、本地终端适配(PowerShell/bash/zsh)、沙箱管理(轻量/容器化)、命令执行引擎、结果读取与整理、本地技能库/环境信息库、通信配置库、执行日志/历史记录库、自然语言输出接口）。当前已实现：工具执行与单Agent。"

## Clarifications

### Session 2026-09-02

- Q: 在 A2A 架构下，主 Agent 之外需要哪些工作 Agent 角色？ → A: 固定三个角色——主 Agent（当前 agent，负责用户交互与整体调度）、业务 Agent、编排 Agent；当任务复杂需要拆解并行时，主 Agent 动态创建 SubAgent（子智能体）承担子任务与命令执行

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 多Agent协作执行混合任务 (Priority: P1)

一名开发者用自然语言提出"分析当前目录的磁盘占用并清理超过 100MB 的临时文件"这类混合任务（既需要推理决策，又需要执行多条命令行操作）。系统自动协调三个固定角色——主 Agent（用户交互）、业务 Agent（业务处理）、编排 Agent（拆解与调度）——并在任务复杂需要并行时创建 SubAgent 执行子任务/命令，将结果整理后以自然语言回复。用户无需手动把任务拆成单条命令。

**Why this priority**: 这是多Agent能力的核心价值——把"推理 + 工具执行"从单Agent升级为角色分工的协作，直接复用已实现的工具执行与单Agent能力，是最小可行增量。

**Independent Test**: 仅实现本故事即可演示价值：用户输入一个混合任务，系统端到端完成并返回结构化结果。可通过"输入任务 → 观察任务完成 → 检查结果正确性"独立测试。

**Acceptance Scenarios**:

1. **Given** 用户已启动 CLI 并处于交互会话，**When** 用户提交一个需要推理 + ≥2 条命令的混合任务，**Then** 系统在无需人工干预的情况下完成全部步骤并以自然语言返回最终结果
2. **Given** 任务执行过程中某个命令失败，**When** 系统检测到失败，**Then** 业务 Agent 根据上下文决定重试或更换方案，并在最终回复中说明失败与恢复情况
3. **Given** 用户处于同一会话中继续提问，**When** 用户追问任务细节，**Then** 系统基于会话上下文直接回答，无需重新执行

---

### User Story 2 - 安全执行与环境适配 (Priority: P2)

用户期望系统在本地终端执行命令时是安全的：系统自动识别当前终端类型（PowerShell / bash / zsh）并适配命令写法，对高风险操作（如删除目录、修改系统配置）在执行前要求用户确认，且命令在受控沙箱中运行，防止误操作破坏用户环境。

**Why this priority**: 安全防护是让多Agent真正可被信任并落地日常使用的前提；环境适配保证在不同开发机上开箱即用。

**Independent Test**: 独立测试：在任一受支持的终端环境中，提交一条高风险命令，验证会触发确认/拦截；提交一条普通命令，验证可正常执行且不要求重复确认。

**Acceptance Scenarios**:

1. **Given** 用户在 bash 终端下使用，**When** 任务包含高风险命令（如删除目录的命令），**Then** 系统在执行前要求用户明确确认，未确认则不执行
2. **Given** 用户在 PowerShell 或 zsh 下使用，**When** 执行同义命令，**Then** 系统自动使用适配该终端的命令写法，无需用户手动配置
3. **Given** 命令在沙箱中执行，**When** 沙箱不可用或执行失败，**Then** 系统返回清晰错误提示，不静默吞掉失败

---

### User Story 3 - 技能注入与知识复用 (Priority: P3)

用户希望系统能复用已沉淀的技能与知识：管理员可在本地技能库/环境信息库中维护常用技能与当前环境信息，系统在任务中自动加载相关技能，并把当前环境信息（目录、可用工具、历史）纳入上下文；用户还能查询过往执行日志与历史记录。

**Why this priority**: 知识复用降低重复解释成本、提升任务准确率；日志/历史为排障与审计提供依据。此故事建立在 P1 的多Agent执行之上。

**Independent Test**: 独立测试：向技能库添加一个技能，然后下达可复用该技能的任务，验证系统自动应用；查询历史记录，验证能返回过往会话与执行结果。

**Acceptance Scenarios**:

1. **Given** 技能库中已存在一个"项目初始化"技能，**When** 用户下达与该技能匹配的任务，**Then** 系统自动调用该技能并完成任务，且回复中说明使用了该技能
2. **Given** 用户询问当前环境信息（如当前目录、可用工具），**When** 系统回答，**Then** 回答内容与真实环境一致，无需用户手动提供
3. **Given** 用户查询执行历史，**When** 用户要求查看某次会话或某类命令的历史，**Then** 系统在数秒内返回对应记录

---

### Edge Cases

- 当用户输入的命令/任务含危险字符或注入风险时，系统如何处理？
- 当沙箱与宿主环境结果不一致（例如沙箱内成功但宿主不可用）时，系统如何向用户说明？
- 当业务 Agent 与 CLI Agent 对任务理解冲突（例如命令重复执行）时，如何避免破坏性副作用？
- 当会话上下文超过限制时，系统如何压缩/丢弃而不丢失关键信息？
- 当本地终端语法差异（如 `ls` 与 `Get-ChildItem`）导致命令失败时，系统如何适配重试？
- 当用户中途取消任务或中断执行时，系统如何清理已启动的进程与状态？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持多Agent协作——用户在一个自然语言会话中提交任务后，系统自动协调主 Agent、业务 Agent 与编排 Agent，并在任务需要拆解并行时动态创建 SubAgent，无需用户手动分派
- **FR-002**: 系统 MUST 自动识别并适配本地终端环境（PowerShell / bash / zsh），用户无需手动声明终端类型
- **FR-003**: 系统 MUST 对高风险操作在执行前请求用户确认；未获确认的命令 MUST NOT 执行（安全防护模块）
- **FR-004**: 系统 MUST 在受控沙箱中执行命令；沙箱不可用时 MUST 给出明确错误提示而非静默失败
- **FR-005**: 系统 MUST 读取命令执行的输出并整理为结构化结果，以自然语言回复用户（结果读取与整理）
- **FR-006**: 系统 MUST 支持从本地技能库自动加载并应用与任务匹配的技能（技能注入）
- **FR-007**: 系统 MUST 将当前环境信息（工作目录、可用工具等）纳入任务上下文，回答与真实环境一致
- **FR-008**: 系统 MUST 持久化执行日志与会话历史，并支持用户查询过往记录
- **FR-009**: 系统 MUST 在会话中保持多轮上下文；上下文超限时压缩而非丢弃关键信息
- **FR-010**: 系统 MUST 在命令失败时基于上下文自动重试或调整方案，并在最终回复中说明

### Key Entities

- **会话（Session）**: 用户与系统的多轮对话上下文，承载输入/输出接口之间的状态
- **Agent 角色（主 / 业务 / 编排 / SubAgent）**: 职责分工的智能体及其各自的推理与执行上下文；主 Agent 负责用户交互，业务 Agent 负责业务处理，编排 Agent 负责拆解与调度，SubAgent 按需动态创建、承担子任务与命令执行
- **命令执行记录（Command Execution）**: 一条命令及其输出、退出状态、耗时、执行环境，是日志/历史的基础单元
- **技能（Skill）**: 从本地技能库注入的可复用能力定义，供任务匹配与调用
- **环境信息（Environment Info）**: 终端类型、工作目录、可用工具等环境快照，供上下文使用
- **日志/历史（Log/History）**: 持久化的会话与执行记录，支持查询与审计

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在 5 分钟内可端到端完成一个含 ≥3 步命令行的混合任务（对比当前需手动拆解命令）
- **SC-002**: 混合任务（含 ≥3 步命令操作）的一次性完成成功率 ≥ 80%
- **SC-003**: 高风险操作在提交执行前 100% 触发确认或拦截，0 例未授权执行
- **SC-004**: 系统在 PowerShell / bash / zsh 三种终端环境中均可开箱使用，无需用户手动配置终端类型
- **SC-005**: 90% 的历史记录查询在 2 秒内返回结果
- **SC-006**: 命令执行后，用户在一次回复内获得结构化结果，无需二次追问

## Assumptions

- 本特性基于已实现的"工具执行 + 单Agent"能力构建；多Agent协调、环境适配、安全防护、技能注入、日志库为本次新增
- v1 沙箱默认采用轻量沙箱；容器化沙箱作为后续增强，不影响 v1 交付
- 安全策略默认：高风险命令需确认，低风险命令自动执行，用户可配置白/黑名单
- 技能库 / 环境信息库 / 日志库使用本地持久化存储，无外部服务依赖
- LLM 能力由现有配置提供，多Agent共享同一 LLM 服务，不引入新的模型供应商
- 跨终端适配以通用命令行为目标；个别命令在特定终端存在差异时，系统以该终端的正确写法重试
- 本特性不包含 GUI、远程/云环境或团队协作功能，属于后续独立特性
