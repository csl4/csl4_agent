## User Scenarios & Testing *(mandatory)*

### User Story 1 - 运行全程可观测、可追溯（Priority: P1）

作为使用 Agent 的工程师/运维，我运行一次任务（含多次 LLM 调用与工具调用），需要看到**一条完整的执行链路**：任务→每一步推理→每次 LLM 调用→每个工具调用，含各自耗时、token 用量、估算费用与最终结果。出问题时我能按链路定位"哪一步错、为什么错"，而不是只看最终回答。

**Why this priority**: 宪法第三条"一切可观测，没有 Trace 不上线"是底线原则。当前项目对执行过程几乎不可见（无链路、无 token/费用视图），无法定位失败根因，是重构最核心的价值。

**Independent Test**: 运行一个会调用工具的任务后，在可观测界面（或导出数据）中能看到一条完整链路：包含 ≥1 次 LLM 调用 span 与 ≥1 次工具调用 span，归属同一链路 ID，且每条 span 带耗时与 token 用量。单此能力即为可用 MVP。

**Acceptance Scenarios**:

1. **Given** 执行一次含工具调用的任务，**When** 运行结束，**Then** 生成一条链路，包含任务→LLM→工具的多级嵌套记录，所有记录共享同一链路 ID。
2. **Given** 上述运行，**When** 查看任意 LLM 调用记录，**Then** 能看到输入/输出 token 数与估算费用，数值与实际用量一致（误差 <5%）。
3. **Given** 运行中出现 LLM 或工具调用失败，**When** 按链路回溯，**Then** 能在对应调用记录上看到错误信息，且失败不影响整条链路其余记录的完整性。
4. **Given** 记录包含敏感内容（完整 prompt/输出），**When** 检查存储数据，**Then** 默认不落盘完整内容；仅当显式开启记录内容开关时才捕获。

---

### User Story 2 - 显式编排：流程可控、可中断、可恢复（Priority: P2）

作为 Agent 开发者，我需要把当前"手写主循环"的流程改造成**显式声明的编排图**：节点（做什么）与边（流程走向）清晰可见；执行中可以安全暂停等待人工确认（人在回环）；任务中断或进程重启后能从断点恢复，不重复已完成的工作。

**Why this priority**: 宪法 3.2 要求"生产编排用 Workflow 定框架 + 局部 Agent 自主的混合模式，确定性流程用显式图"。显式编排是可观测、可测试、可恢复的前提，也是后续多 Agent 扩展的基础。

**Independent Test**: 运行一个触发人工确认的任务，在确认节点暂停；提供确认后继续完成，已执行的步骤结果不丢失。单独实现此能力即为一独立可用的编排改造。

**Acceptance Scenarios**:

1. **Given** 一个多步骤任务，**When** 到达需要人工确认的步骤，**Then** 执行暂停并等待；确认后从该步骤继续，不重复此前已完成步骤。
2. **Given** 上述运行在确认节点恢复后，**When** 观察结果，**Then** 与"未暂停直接执行"的任务在最终输出上一致。
3. **Given** 执行流程用显式图声明，**When** 开发者查看流程定义，**Then** 能列出全部节点、各节点职责、节点间的条件分支与走向。
4. **Given** 主循环受最大步数限制，**When** 某任务达到上限或陷入重复调用，**Then** 强制终止并返回已得的部分结果，不无限循环。

---

### User Story 3 - 全链路安全护栏与审计留痕（Priority: P3）

作为安全管理员，我需要确认所有进入/离开 Agent 的内容与工具执行都经过安全校验：恶意注入被拦截、非法命令/路径被拒、高风险写操作有人工确认，且每次拦截/确认都留痕可查，敏感信息脱敏。

**Why this priority**: 宪法第十一章三道 Guardrail（输入/输出/结果侧）与审计要求。当前已有命令/路径守卫与 HITL，但输入侧（防注入/内容合规）与输出侧（格式校验/敏感过滤）未闭环，需补齐并统一接线。

**Independent Test**: 构造一个包含恶意指令的输入与一个非法命令调用，分别验证被拦截且审计留痕。此能力独立于编排与可观测，可单独交付。

**Acceptance Scenarios**:

1. **Given** 输入包含注入性指令或违规内容，**When** 进入系统，**Then** 被输入侧护栏拦截并记录，拦截记录可查询。
2. **Given** 触发高风险写操作（如删除、外部副作用），**When** 执行前，**Then** 出现人工确认环节；确认与拒绝均有审计记录。
3. **Given** 工具返回结果进入下一轮推理前，**When** 结果异常（格式错误/越界值），**Then** 被结果侧校验发现并降级处理，错误结果不污染后续推理。
4. **Given** 审计日志，**When** 检查记录内容，**Then** 密钥类字段被脱敏，不以明文留存。

---

### Edge Cases

- LLM 或工具后端不可用时（超时/熔断），链路如何标记降级/重试，部分结果如何返回。
- 任务在人工确认节点挂起期间进程重启：断点与待确认状态是否保留、如何恢复。
- 链路 ID 在并行工具调用、多 Agent 场景下如何传播，如何保证归属唯一且不交叉。
- 敏感内容开关关闭时，token/费用/耗时等指标是否仍完整（指标与内容解耦）。
- 可观测后端未部署/不可达时，Agent 主流程是否照常运行（可观测不得成为可用性依赖）。
- 步数熔断与死循环检测同时触发时，返回的部分结果如何标记不完整。
- Guardrail 误拦正常操作时的恢复路径（人工放行/降级）与审计标记。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为每次任务执行生成一条贯穿任务→步骤→LLM 调用→工具调用的完整链路，链路各层记录共享同一链路 ID，且可被查询导出。*（宪法 13.1 三层 Trace）*
- **FR-002**: 系统 MUST 记录每次 LLM 调用的输入/输出 token 数与估算费用，并可按链路/任务聚合汇总。*（宪法 13.1 / 操作文档 6.1）*
- **FR-003**: 系统 MUST 用显式声明的编排图驱动 Agent 主流程，流程定义可列出全部节点、边与条件分支。*（宪法 3.2）*
- **FR-004**: 系统 MUST 支持执行中断与恢复：人工确认节点暂停、确认后继续、中断恢复后不重复已完成步骤。*（宪法 11.2 / 操作文档 2）*
- **FR-005**: 系统 MUST 在 Agent 步数超限（默认 20，可配置）或连续重复调用时强制终止并返回部分结果。*（宪法 2.3 / 附录 A）*
- **FR-006**: 系统 MUST 在输入侧拦截注入性/违规内容，在输出侧校验结构合法，在结果侧校验工具返回值，任何一侧拦截均留审计记录。*（宪法 11.1 三道 Guardrail）*
- **FR-007**: 系统 MUST 对敏感内容默认脱敏：完整 prompt/completion 不落盘，仅当显式开关开启时捕获；密钥类字段在审计/可观测数据中不以明文出现。*（宪法 11.1 / 操作文档 10）*
- **FR-008**: 系统 MUST 将既有可观测事件流（事件→指标快照→状态快照）接入运行时主循环，事件真实随执行产生并可查询。*（GSDOC/agent1.md 已落地模型接线）*
- **FR-009**: 系统 MUST 保持可观测后端厂商中立：切换/替换可视化后端（如 Jaeger ↔ 其他）不改 Agent 主流程代码。*（操作文档 1 / 宪法 13.1）*
- **FR-010**: 系统 MUST 在可观测后端不可达时照常完成 Agent 执行，可观测层失败不得阻塞主流程。*（操作文档 11 排查清单 / 宪法五条之五）*
- **FR-011**: 系统 MUST 保持既有用户接口（CLI 命令、配置项、事件输出流）兼容，重构不改变用户可见行为。*（宪法 14.2 可回滚）*
- **FR-012**: 系统 MUST 提供可观测接入的开关配置，默认在启用后通过测试验证链路完整、指标准确。*（宪法 14.1 变更流程）*
- **FR-013**: 系统 MUST 用显式编排图（LangGraph StateGraph）重写现有手写主循环，且迁移后既有能力行为不变：人工确认（HITL）暂停/恢复、前端暂停、上下文压缩、并行工具执行。*（已确认：LangGraph 显式图重写）*
- **FR-014**: 系统 MUST 采用「自动埋点 + 手动业务 span 叠加」的双层可观测结构：技术细节（LLM/工具调用）由自动埋点覆盖，节点级执行由手动业务 span 承载业务语义。*（已确认：方案 A + 手动叠加）*
- **FR-015**: 本次重构范围限定为四项核心差距：①LangGraph 显式编排 ②OpenTelemetry 可观测接入 ③Guardrail 输入/输出侧补齐 ④可观测事件流接线；RAG/多租户/后端服务治理不进本次。*（已确认：聚焦核心差距）*

### Key Entities *(include if feature involves data)*

- **执行链路（Trace / Span）**: 一次任务执行的全过程记录；链路含任务级、步骤级、LLM/工具调用级三层嵌套记录，每层含耗时、状态、计量（token/费用）与归属 ID。
- **编排图**: Agent 主流程的显式声明（节点=处理单元，边=走向/条件分支）；支持暂停、恢复、并行分支。
- **事件流与指标快照**: 运行时逐事件产生的记录（生命周期/LLM/工具/规划/审批等），经聚合生成只读指标快照（Agent/Task 维度），是链路与指标的数据源。
- **Guardrail 与审计记录**: 输入/输出/结果三道校验的拦截结果、HITL 确认记录，全部留痕且敏感字段脱敏。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 的可观测运行（开关开启时）都能导出贯穿任务→步骤→LLM→工具的完整链路，每层带耗时与状态。
- **SC-002**: 每次 LLM 调用的 token 与费用记录与真实用量一致，聚合误差 <5%。
- **SC-003**: 接入可观测后任务完成率不下降，P95 端到端耗时增幅 ≤20%（可观测开销可控）。
- **SC-004**: 100% 的触发式高风险写操作在执行前有人工确认节点，且确认/拒绝均可审计追溯。
- **SC-005**: 中断后恢复的任务，已完成的步骤结果 100% 不丢失、不重复执行。
- **SC-006**: 输入/输出/结果侧 Guardrail 对全部注入与非法调用样本拦截率为 100%，且逐条留痕；审计与可观测数据中敏感密钥字段明文出现率为 0。
- **SC-007**: 重构后既有 CLI 命令与配置兼容，回归运行通过（现有行为无破坏性变更）。
- **SC-008**: 可观测后端停机时，Agent 任务完成率不受影响（与后端在线时一致）。

## Assumptions

- **需求基准**：GSDOC 目录是本次重构的需求来源；`agent1.md` 为历史设计草案，其已落地模型（`GSagent/core/observability/`）直接复用，不再重造。
- **向后兼容**：重构以"不改变用户可见行为"为前提——现有 CLI 命令集、配置 schema、工具集插件、策略组件全部保留；`agent run` / `agent chat` / `agent serve` 等行为不变。
- **复用既有资产**：已落地的可观测对象模型（Pydantic v2 事件信封/指标/状态）、政策层（PathGuard/CommandGuard/HitlPolicy/AuditLog）、截断（Compactor/Limiter）、多 Agent 角色（BaseAgent 体系）与 A2A 协议映射均复用，不重写。
- **范围边界（已确认）**：本次聚焦四项核心差距——LangGraph 显式编排、OTel 可观测接入、Guardrail 输入/输出侧补齐、可观测事件流接线。不新增 RAG/向量库、不新增多租户 SaaS 化、不重构 CLI 用户接口、不动后端服务并发治理。
- **编排迁移（已确认）**：用 LangGraph StateGraph 显式图重写现有手写主循环（`GSagent/core/agents/tool_calling_llm.py`），保留 HITL 暂停/恢复、前端暂停、压缩、并行工具执行等既有能力，行为向后兼容。
- **可观测方案（已确认）**：采用操作文档方案 A（OpenLLMetry 自动埋点）叠加手动业务 span 的双层结构；GenAI 语义约定（`gen_ai.*`）标记 LLM 调用；节点级 span 标记业务语义；指标（token/费用/耗时）与内容解耦。
- **可观测后端**：开发/演示默认本地 Jaeger（Docker 启动），厂商中立可替换为 Tempo/LangSmith/Phoenix。
- **依赖**：允许新增可观测性相关依赖（OTel SDK/导出器、编排图依赖），以不破坏既有 `litellm` 统一供应商抽象为前提。
- **隐私合规**：默认不采集完整 prompt/completion，指标（token/费用/耗时）与内容解耦。
